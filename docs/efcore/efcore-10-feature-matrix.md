# EF Core 10 功能矩阵

这是 EF Core 10 Provider 的完整功能矩阵，也是功能范围和验收标准的唯一来源。每一行分别记录 MySQL 和 Oracle；`Done` 只表示该行和该模式满足本矩阵的验收要求。当前开发顺序和提交队列见 [开发进度](efcore-10-progress.md)，未完成项按责任边界见 [功能缺失矩阵](efcore-10-gap-matrix.md)。

## 范围和状态

- Provider 负责 EF Core 服务注册、模型缓存、类型映射、SQL 翻译、参数/reader 适配、物化、写入编排、事务编排和错误边界。
- Connector 负责 ADO.NET 协议、认证、TLS、Proxy/OB20、连接池、wire timeout/cancellation、参数 codec、reader 传输和原生事务句柄。
- OceanBase 服务端负责 SQL 解析执行、类型/精度、权限、约束、DDL、生成值和事务结果。
- 只有 Provider 本地证据的行仍是 `In progress`；interceptor/fake reader/SQL shape 不能替代真实 OceanBase 结果。
- `Deferred` 是当前发布明确不做的功能，不得宣传为支持；不是 Provider 当前缺陷。

| 状态 | 含义 |
| --- | --- |
| `Done` | 代码、测试、规定证据和模式验收全部完成。 |
| `In progress` | 有部分代码或证据，但仍有实现、测试、live 或发布缺口。 |
| `Planned` | 需要开发，尚无足够实现证据。 |
| `Deferred` | 当前发布范围之外，保留明确拒绝行为。 |
| `Blocked` | 有外部阻塞，不能当作通过。 |

## 每行 Done 的最低标准

行为、正向用例、NULL/空值/边界、明确拒绝用例、同步/异步、MySQL/Oracle、代码走查和必要的 package consumer 必须齐全。运行时行还要有声明环境的 `Live` 结果；没有 live 环境时只能保持 `In progress`，并在缺失矩阵标明责任归属。

and explicit Prepare. D-suffixed SQL literals pass independently. This remains an unresolved
Connector/server carrier boundary; the Provider does not add a transport workaround.

The national-literals module also adds MAP-06 explicit national-declaration/clone coverage and
MAP-07 converter literal coverage. The [ordinary-literals module](efcore-10-ordinary-literals-plan.md)

sync/async query constants pass locally; live UTF8MB4/latin1 CR/LF/CRLF, 4000-character query values,
4000-LF/2000-CRLF density, CHAR comparisons and unencodable-value rejection pass. Release suites on EF10.0.0 and isolated
EF10.0.14 each pass 6628 tests with 16 existing skips; packed consumers pass both modes/patches.
Only generated defaults/HasData SQL were checked locally; no native Schema/DML acceptance is inferred.

The subsequent [bounded text storage module](efcore-10-text-storage-plan.md) adds native
MAP-03/06/07 and narrow SCH-02/UPD-01/02 evidence: unique owned tables, ordinary/national
32-scalar variable text, 8-character fixed padding, NULL/empty, converter bounds, generated
defaults/HasData and tracked insert/update/delete pass in both modes sync/async. MySQL also
passes NO_BACKSLASH_ESCAPES; Oracle RETURNING explicitly opts into Connector PrepareExecute.
MySQL default-safe UTF-8 character literals replace CONVERT expressions, and generated-value
readback drains before commit. This does not close broad parent requirements or LOB/BYTE gaps.

The subsequent [large-text module](efcore-10-large-text-plan.md) adds native ordinary Oracle
CLOB and MySQL LONGTEXT parameter/reader/converter evidence beyond 4000/32767 characters,
including NULL/empty and 65537-character tracked updates with mixed suffixes. Oracle BYTE
tests verify server AL32UTF8, exact capacity/padding, local scalar overflow and native 12899
with preserved native error codes/entries. Native NCLOB DDL returns 902 on target 4.4.2.2, also
through direct Connector; the two explicit rejection tests are not national-LOB acceptance.

The [binary/Guid storage module](efcore-10-binary-guid-storage-plan.md) adds exact native
byte sequences and Guid server-byte checks. Oracle BLOB empty parameters/defaults/seed
preserve non-null zero length; RAW empty inputs reject. MySQL BINARY padding and
VARBINARY(262144), Oracle RAW(2000), and 131073-byte BLOB/converter updates pass.
Guid binary storage uses EF/.NET mixed-endian Guid.ToByteArray bytes, independently
verified with HEX/RAWTOHEX; text uses canonical D format. Versioned MySQL LOB DEFAULT
rejection (1067) is a server boundary, not positive default acceptance.

## Definition of complete and development order

For every required ID: document behavior, implement it, pass both-mode evidence at the required layer,
cover negative/boundary cases and update consumer/package impact. Record live environment and tested revision.
An unavailable or skipped required live test leaves its gate open. Missing additional proxy/TLS/HA/compression
or server-version environments limits the support claim; it neither invalidates a tested direct environment
nor establishes a provider defect.

Use the Connector capability boundary recorded in [development progress](efcore-10-progress.md).
An unavailable direct connection blocks live acceptance, not unrelated local Provider implementation.
Continue the local development queue while keeping the affected rows In progress; do not add excluded
or frozen Connector proxy/OB20 capabilities as EF requirements.

Release requires every `Required` row to be `Done`, no failing required tests, explicit deferred limitations and
release-branch package evidence. Do not derive completion percentages from test counts or unequal feature rows.
Tested development checkpoints may be committed on `efcore/10.0` before all rows finish; these are not
release candidates.

Implement in this order:

1. Retain CON-02/UPD-04 cleanup regressions; finish opened-connection ownership/mode evidence.
2. Complete MOD/MAP contracts before expanding SQL; close precision and Oracle text gaps first.
3. Complete QRY/UPD together with TXN evidence on both live modes.
4. Define/implement SCH profile; document unsupported operations before exposing them.
5. Finish specification, packed-consumer, patch-compatibility and release records.

The [development progress](efcore-10-progress.md) tracks the queue; this matrix decides acceptance.
For EF8/EF9 and future EF11, adapt the inventory after reviewing that major's contracts, keep stable IDs for
unchanged behavior and collect new evidence. EF10 status never automatically transfers to another branch.
